# Трава-заполнение и биомы

## Что подключено

`grass` остаётся обычным пропсом. `grass2` и `grass3` — независимый слой
заполнения, запекаемый в пространственные ячейки MultiMesh. У травы собственные
веса и генератор случайных чисел: изменение урны деревьев не меняет случайные
кандидатные позиции травы (принятые позиции всё ещё зависят от занятости места).

Материалы `grass2` / `grass3` используют двусторонний **alpha scissor**, а не
alpha blend: это устраняет необходимость сортировать тысячи полупрозрачных
карточек. Исправлены точки посадки карточек; исходные PNG не изменены.

По умолчанию работают четыре профиля из `data/biomes/`:

| Профиль | Заполнение | Плотность относительно общей |
| --- | --- | --- |
| `forest` | grass2, редкие грибы | 1.0 |
| `rocky` | grass3 | 0.3 |
| `meadow` | grass2, grass3, редкие цветы | 1.35 |
| `roadside` | grass2, grass3 | 0.65 |

Биомы используют существующие тематические зоны лес/скалы/поле/ралли, чтобы
трава и крупные объекты не образовывали две несогласованные раскладки. Зоны
выбираются детерминированно по сиду и дистанции, отдельно на каждой стороне
трассы. Это не климатическая симуляция: состав задают профили, а высота и уклон
фильтруют пригодность конкретной точки для вида.

Длина участка — `RallySceneryConfig.biome_length` (по умолчанию 120 м).
Между крупными пропсами разных зон сохранён свободный переход. Плотность травы
меняется плавными **мировыми пятнами**, а не равномерным шумом на каждом кадре.
Пятна не привязаны к границам стриминговых чанков. Состав видов меняется на
границах тематических участков; смешивание климатических биомов не моделируется.

## Добавить новый вид травы — без правки генератора

1. Создайте `scenes/props/my_grass.tscn`: корень `Node3D`, меши над землёй,
   начало координат в точке посадки. Для текстурированных карточек используйте
   двусторонний alpha scissor, для текстур включите mipmaps.
2. Откройте `data/stage/default_prop_library.tres`, добавьте новый `RallyProp`
   в `props`, задайте уникальный `id`, `display_name` и `scene`.
3. Включите **ground_cover**. Обычный `weight` можно оставить 0 — слой
   заполнения использует отдельный **cover_weight**.
4. Задайте **biome_ids**: например `["forest", "meadow"]`. Пустой список — все
   биомы. Эти ограничения применяются и к обычным пропсам при выборе урны.
5. Настройте `size`, `width_jitter`, `height_jitter`, `y_offset`,
   `placement_radius`, при необходимости `min_offset` / `max_offset`.
6. Настройте **cover_max_slope** (градусы) и **cover_altitude** (мировые метры).

Больше нигде новый id прописывать не нужно: и генератор, и прогрев стриминга
читают один список библиотеки. `cover_weight = 0` отключает вид в заполнении.
Старый `ground_cover_prop_ids` поддерживается для совместимости, но его очистка
не выключает виды с флагом `ground_cover`. Для полного отключения слоя задайте
`ground_cover_density = 0`.

## Настройка плотности

В `data/stage/default_scenery.tres`:

- `ground_cover_density` — общая плотность (сохранено текущее значение 10.9);
- `ground_cover_attempts_per_step` — базовое число попыток на шаг и сторону;
- `ground_cover_success_chance` — вероятность успешного кандидата;
- `max_attempts_per_step` и `max_instances` — общие ограничения стоимости;
- `biomes` — профили заполнения; первый профиль соответствующей зоны активен.

В каждом `RallySceneryBiome`:

- `cover_density` — множитель плотности биома, 0 отключает заполнение в нём;
- `cover_size` — дополнительный диапазон масштаба;
- `patch_size` — размер плавных пятен в мировых метрах;
- `patch_floor` — минимальная плотность между пятнами (1 — без пятен).

Пустой список `biomes` сохраняет равномерное заполнение старых пользовательских
конфигов. При этом фильтрация по биомам отключается.

Заполнение учитывает дорожный коридор, соседние витки, границы terrain_rect,
отступы вида, высоту, уклон и свободное место. Трава не резервирует место в сетке
крупных объектов, поэтому не вытесняет деревья на следующих шагах. Общий бюджет
`max_instances` включает все виды. Коллизии у заполнения не создаются, тени
выключены, дальность берётся из `scenery_range_small`, даже если `small` не отмечен.
На стриминговых этапах цикл заполнения уступает кадр по существующему бюджету
`STREAM_SLICE_USEC`, а сцены новых видов заранее запекаются при загрузке.

## Пять новых пропсов

| id | Сцена | Применение |
| --- | --- | --- |
| `juniper` | `scenes/props/juniper.tscn` | Можжевельник, лес |
| `dry_shrub` | `scenes/props/dry_shrub.tscn` | Сухой ветвистый куст, скалы |
| `moss_rock` | `scenes/props/moss_rock.tscn` | Небольшой замшелый камень, лес |
| `mushroom_cluster` | `scenes/props/mushroom_cluster.tscn` | Редкое лесное заполнение |
| `wildflowers` | `scenes/props/wildflowers.tscn` | Редкое луговое заполнение |

Все пять имеют оригинальные процедурные текстуры в `textures/environment/`:
`juniper_needles.png`, `dry_branches.png`, `moss_stone.png`, `mushroom_cap.png`,
`wildflowers.png`. Текстура сухих веток также используется ножками грибов.
Это небольшие пиксельные текстуры под существующий low-poly/PS1 стиль проекта.

Повторная генерация **только новых** сцен и текстур:

```sh
python3 -m pip install Pillow
python3 tools/make_biome_props.py
```

Скрипт детерминированный; существующие авторские ассеты не перезаписывает.
Ручные изменения новых пяти сцен будут перезаписаны при его повторном запуске.

## Проверки

```sh
python3 tools/check_project.py
python3 -m unittest discover -s tests -p 'test_*.py'
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/biome_ground_cover.gd
godot --headless --path . --script res://tests/scenery_generation.gd
godot --headless --path . --script res://tests/streamed_world.gd
```

Новый тест проверяет подключение вида без id в конфиге и без крупных пропсов,
нулевые плотности и веса, бюджет, повторяемость, пригодность биома/высоты,
отсутствие травы на дороге, сохранение alpha scissor после запекания и
непрерывность пятен. Визуальную оценку размеров и плотности проводите в Godot
на реальной трассе после импорта текстур.
